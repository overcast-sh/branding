# design-sync notes — @overcast-sh/branding

- **This repo is not a component library.** The Storybook (`.storybook/` at root) is an all-MDX brand book — zero CSF stories — so the storybook shape's compare pipeline has nothing to pair. `shape: "package"` is pinned deliberately; don't "fix" detection back to storybook.
- **No dist.** There is no package build; the sync entry is the authored `design-system/react/index.ts` (`cfg.entry`), which exports the four asset wrappers plus the five brand-book primitives re-exported from `stories/brand.tsx`.
- **Asset wrappers embed generated SVGs.** `design-system/react/assets.generated.ts` is produced by `design-system/react/embed.mjs` from `logo/ mark/ icons/ loading/`. After `gen.ts` changes and `npm run build`, run `node design-system/react/embed.mjs` (that's `cfg.buildCmd`) or the wrappers ship stale artwork.
- **Fonts:** `design-system/fonts.css` uses absolute `/fonts/` URLs (Storybook static mount) which the converter can't resolve; `.design-sync/fonts.css` is the sync-owned copy with repo-relative paths (`cfg.extraFonts`). Keep the two in sync. Fonts are TTF only — no woff2 in the repo.
- **Tokens** ship via `cfg.cssEntry = design-system/tokens.css` (appended into `_ds_bundle.css`). The `tokens/` dir of the bundle stays empty: `tokensPkg`/`tokensGlob` only read from node_modules packages, and this repo's tokens are local files. `tokens.json` / Tailwind variants therefore don't ship — the README conventions header carries the token vocabulary instead.
- **Groups** come from `.design-sync/docs/*.md` frontmatter (`Brand` / `Brand book`) — those docs are also each component's `.prompt.md`. Without them, path-derived groups would be wrong (`stories`, `react`).
- **npm quirk (this machine):** npm has allow-scripts protection; postinstall scripts (esbuild, playwright) are skipped with a warning — harmless so far. `npm ci` fails EPERM if the repo's Storybook dev server is running (esbuild.exe / native module locks) — stop it first.
- **Playwright:** chromium build 1208 is cached on this machine → playwright pinned to 1.58.0 in `.ds-sync/` (latest wanted 1234 = 200MB re-download).

## Re-sync risks

- **`assets.generated.ts` can silently go stale.** The wrappers embed SVG strings generated by `design-system/react/embed.mjs`. If `gen.ts`/`npm run build` regenerate the SVG assets and nobody re-runs embed (it's `cfg.buildCmd`, so the driver runs it — but a bare converter invocation without buildCmd wouldn't), the components ship the old artwork while the repo's SVGs have moved.
- **`cfg.dtsPropsFor` duplicates the component APIs by hand** (no .d.ts tree exists to extract from — the extractor is .d.ts-only and this repo has no package build). If props change in `design-system/react/*.tsx` or `stories/brand.tsx`, the config bodies must be updated by hand or the design agent sees a stale contract. Same for `.design-sync/docs/*.md`.
- **`.design-sync/fonts.css` mirrors `design-system/fonts.css`** — if the repo adds weights or switches to woff2, update the sync copy.
- **`.d.ts` parse check never ran** (typescript not in repo node_modules) — the `dtsPropsFor` bodies are hand-validated only.
- **Loader animation is SMIL** (`<animate>`), frozen by the capture harness — verified as a static frame; the blink itself was not machine-verified.
- **Conventions header names the token vocabulary** — if tokens are renamed in `tokens.css`, re-run the header validation grep (all `--oc-*` names + `.oc-cursor-blink` against `ds-bundle/_ds_bundle.css`).
- **Known render warns:** none outstanding (the earlier `[RENDER_THIN]`/`[RENDER_BLANK]` were unauthored floor cards, all cleared by authored previews; `[GRID_OVERFLOW]` on Logo resolved via `cardMode: "column"`).
